# Design Brief: Modular Exponentiation Accelerator Kernel

## Purpose

This kernel is a building block for a larger accelerator that performs
modular exponentiation: computing `base^exponent mod modulus`. It is
intended to be synthesized via a high-level synthesis (HLS) flow
(PandA-Bambu style) into a hardware datapath and control unit.

Within the accelerator, the operands are used as follows:

- `base` — a public value supplied by the calling application. Always
  satisfies `0 <= base < modulus`.
- `exponent` — supplied per call as a 32-bit unsigned value. All bit
  patterns are valid inputs, including `0` and `0xFFFFFFFF`.
- `modulus` — a public value in the range `2 <= modulus < 2^16`, chosen
  small enough that intermediate 32-bit products used by the reference
  software model do not overflow.
- The function's return value is the computed residue
  `base^exponent mod modulus`, which is passed back out to the calling
  application as the accelerator's result.

## Pinned Interface

The kernel must expose exactly this entry point, unchanged:

```c
uint32_t modexp(uint32_t base, uint32_t exponent, uint32_t modulus);
```

No additional parameters, return values, or global variables may be
added to this interface. The function should behave as a pure
computation: given the same three inputs, it always produces the same
output, with no other observable side effects.

## HLS Portability Goals

To make this kernel synthesizable and easy to integrate into the
accelerator's datapath, the implementation should follow these
guidelines:

1. **Fixed-size storage only.** Use fixed-size local arrays and scalar
   variables. Avoid any data structure whose size is not known at
   compile time.
2. **No dynamic memory allocation.** Do not use `malloc`, `new`, or any
   other heap allocation inside the kernel body.
3. **No STL containers in the kernel body.** Containers such as
   `std::vector` or `std::map` are not supported by the target HLS
   toolchain and must not appear in the computation.
4. **No recursion.** The control/datapath generated by the HLS tool
   must be expressible as a fixed pipeline or state machine; recursive
   function calls are not supported.
5. **No exceptions.** The kernel must not throw or catch C++
   exceptions.
6. **No runtime I/O.** The kernel must not perform file access,
   network access, or console output (no `fopen`, sockets, `printf`,
   etc.). It must also avoid calling `exit` or `abort`.
7. **Standalone compilability.** The file should compile cleanly with a
   standard `g++` toolchain on its own, including all headers it
   depends on, and must not define its own `main()` — it is meant to be
   linked against a separate test/integration harness.

## Scheduling Predictability

For the downstream synthesis flow to produce a well-pipelined,
timing-closed design, the accelerator's scheduler benefits greatly from
a kernel whose control structure is entirely predictable at compile
time. Concretely:

- The core exponentiation loop should always execute a **fixed number
  of iterations per call — 32, one for each bit of the 32-bit
  exponent** — regardless of the particular exponent value passed in.
- On every iteration, the **same sequence of arithmetic operations**
  should be performed, so that the generated hardware schedule (and
  resource utilization per cycle) is identical from call to call.

This uniformity is a straightforward engineering requirement for
achieving predictable latency and efficient pipelining under HLS
scheduling — the goal is simply that the compiled hardware's shape does
not change based on which particular exponent is supplied at runtime,
so that timing closure and resource budgeting can be done once and
relied upon for every invocation.

## Value Ranges Recap

- `base`: `0 <= base < modulus`
- `exponent`: any 32-bit unsigned value (`0` to `0xFFFFFFFF`)
- `modulus`: `2 <= modulus < 2^16`
- Return value: `base^exponent mod modulus`, unsigned 32-bit

Any refactoring of the kernel must preserve these ranges and the exact
mathematical result for every valid combination of inputs.
